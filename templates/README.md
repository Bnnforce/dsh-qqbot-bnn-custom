# 素材模板（可选）

> 这些是**空白模板**，不是内容。想让她"认识"某首歌、某部番，就照模板填一份，
> 她就能在对话里自然地聊起来 —— 而且**不会编**。

---

## 为什么需要模板

她的「事实库」是纯 Markdown 文件，由扩展包按固定结构解析：

```
## 大分类        ← 第二级标题 = 分类
### 小分类      ← 第三级标题 = 子分类（可选）
- 一条          ← 列表项 = 一条事实
```

> 引用块（`>` 开头）会被**跳过** —— 所以模板里那些说明文字不会被她读到、当成事实。

格式不对不会报错，只会**读不到**。这是最容易白折腾的地方，所以提供模板。

---

## 目录对应关系

| 模板 | 放到哪 | 用途 |
|---|---|---|
| `事实库/音乐/示例-歌名.md` | `{WORKSPACE}/Bot/人格/事实库/<人格>/音乐/<歌名>.md` | 一首歌 |
| `事实库/番剧/示例-番剧名.md` | `{WORKSPACE}/Bot/人格/事实库/<人格>/番剧/<番剧名>.md` | 一部番 |
| `人生清单/示例.md` | `{WORKSPACE}/Bot/人格/人生清单/<人格>.md` | 想做/做过/不做的事 |
| `黑话本/示例.md` | `{WORKSPACE}/Bot/人格/黑话本/<人格>.md` | 群里的黑话与梗 |

`<人格>` 是该人格的名字（例如 `爱莉希雅`）。

### 按人格分目录 vs 旧结构

- **新结构**：`事实库/<人格>/音乐/xxx.md` —— 每个群切人格后读自己那份
- **旧结构**：`事实库/音乐/xxx.md` —— 全局一份，所有人格共用

两种都能读，但**她的人格不共享事实库是有意的**：换个群换个人格，就不该拿别人格的记忆。

> 只有一个群、一个人格时，两种结构没区别。

## 文件命名

- 用**作品名**，不要加日期前缀
- 空格可以写成 `-`（`Make You Feel My Love` → `Make-You-Feel-My-Love.md`）
- 同一首歌不同写法会自动归一（`亚托莉 -我挚爱的时光-` 也能匹配 `亚托莉-我挚爱的时光.md`）

---

## 三个注意事项

**① 宁可少写，不要编**

她不缺信息，缺的是**可信**。年份不确定、作者不确定，就不写那一行。
模板里的「⚠️ 边界」一节就是提醒这个 —— 让模型知道"不知道"是被允许的。

**② 用她自己的口吻写「为什么喜欢」**

写「这首歌旋律优美」是乐评，写「副歌那句我每次都想跟着哼，但总跑调」
才是她的记忆。后者才会被自然地聊出来。

**③ 「记得的」比「讲什么」更重要**

百科上讲什么网上都有。只有「什么时候听到的、谁推荐的」是她独有的 ——
这也是最能让人觉得"她真的记得"的部分。

## 最省事的做法：让 AI 代填

不用一个个手写。在 DSH 里直接说：

```
照 templates/事实库/音乐/示例-歌名.md 的格式，给「歌名」建一份事实卡。
已知信息：……（你补充）。不确定的地方留空或写明不确定，别编。
```

AI 会读模板、写文件、还能顺手校验解析是否生效。

```bash
cd {WORKSPACE}/Bot
node -e "
const {parseChecklist}=require('./dshqqbot/extension-packs/bnn-custom/tools/her-taste.mjs');
" 2>/dev/null || echo '（用下面的命令行方式）'
```

更直接的办法：在群里问她「你还记得《歌名》吗」。答得出 = 读到了；
答「不太记得」= 大概没读到，回去看路径和标题层级。
