# 扩展点速查

> 六套代码扩展点，**每套的导出形态完全不同**，认错了不会报错，只会**静默跳过**。
> 这份是「写之前先对一眼」的清单，坑都是从真实事故里捡的。

---

## 0. 先记这条

**加载失败 = 静默的。** 插件对扩展的容错是 `try/catch` + `logger.warn`，所以：

- 导出形态不对 → 跳过，不报错
- 顶层抛错 → 跳过，不报错
- 依赖 import 不到 → 跳过，不报错

**判断「我的扩展到底加载了没有」，不能看有没有报错，要看日志和行为。** 见 §7。

---

## 1. `inbound/` —— 入站中间件

### 导出形态（三选一，必须命中一个）

```js
// ① 早挂点（推荐；在记群历史之前）
export async function onInbound(ctx, next) { ... }

// ② 晚挂点（在 @门控之后）
export async function onDecide(ctx, next) { ... }

// ③ 裸函数默认导出 = 晚挂点
export default async function (ctx, next) { ... }
```

> ⚠️ **`export default { name, run }` 这种对象形态不被识别**（`run` 不在候选集里）。
> 这是最容易犯的错：照 `tools/` 的壳写 inbound，结果每次启动被跳过，功能从未生效。

### 能干什么

| 动作 | 写法 | 语义 |
|---|---|---|
| 改写文本 | `ctx.rewrite({ text, reason })` | **参数是对象，不是字符串**！传字符串会被拒绝并 warn |
| 消灭整条 | `ctx.annihilate(reason)` | 早挂点：链停 + 群历史不记；晚挂点做不到 |
| 强制唤醒 | `ctx.state.qqInboundForceWake = true` | 跳过 @ 门控 |
| 放行 | `await next()` | **必须调**，不调等于整条吞掉 |

### 坑

- **早挂点读不到 `ctx.state.mention`**（那是 `mentionGate` 之后才有的）。要判「有没有@我」用 `ctx.platform.mentioned`。
- `ctx.rewrite` 收对象：`{ text: '新文本', reason: '为什么改' }`。
- 这是**每条消息**都跑的热路径。别在这里做同步写盘、`Object.keys(ctx)` 反射、网络请求。

## 2. `outbound/` —— 出站装饰

### 导出形态

```js
export default async function onOutbound(ctx, next) { ... }
```

### 关键字段

| 字段 | 含义 |
|---|---|
| `ctx.text` | 当前正文（可用 `ctx.rewrite(新文本)` 改） |
| `ctx.kind` | `'text'` / `'markdown'` / `'card'` / 媒体类型 —— **按需过滤，别对卡片做文本清洗** |
| `ctx.isLastChunk` | 是否最后一段（分段发送时前几段是 false） |
| `ctx.annihilate(reason)` | 丢弃这条 |
| `ctx.send(text)` | 额外发一条（走「先被动后主动」通道） |

### 坑

- **执行顺序 = 文件名升序**。`05-` 在 `60-` 之前跑。改文件名 = 改顺序。
- 多个扩展会**依次改写同一段文本**。你的输出会被后面的扩展再处理一遍。
- 对**所有** `kind === 'text'` 生效的清洗逻辑要格外小心：它会把别人的正常内容一起洗掉。
- 别剥 `<@openid>` / `[rf:xxx]` 这类标记 —— 它们归其他环节管（`10-ensure-at-back`、上游 `markers.js`）。

## 3. `hooks/` —— 启动钩子

### 导出形态

```js
export async function run(env) { ... }
export function dispose() { ... }
export default { name, run, dispose };
```

### 能拿到

`env` 含 `caps`（能力包）、`dataRoot`、`logger`、`kernel`。

### 坑（最要命的两个）

- **`caps` 里没有 `sender` / `replyTarget`** ⇒ `caps.text()` / `caps.markdown()` 在 hook 里**恒 false**。
  想主动说话只能用 `caps.wakeTo`。
- **顶层绝不能有副作用**。hook 是 `await import()` 加载的，**顶层代码会被执行**：
  - 顶层 `process.exit()` → **整个 QQBot 进程被杀**（真实事故）
  - 顶层写盘 / 抛错 → 加载失败被跳过

  需要复用的逻辑拆成两层：`lib/pure/*.mjs`（纯函数、零副作用）+ `scripts/*.mjs`（CLI，只有直跑才 exit）。

### 定时器

要周期执行，用 `registerWithFallback(runKey, fn, { env, fallbackMs, ... })`
（来自 `hooks/zz-central-scheduler.mjs`）：这会让「任务中心」接管调度，
引擎接管后自动清掉自带定时器，引擎掉线会重新武装。

> 注意：如果你的 `run()` 第一行是 `if (!cfg.enabled) return`，那么在**读不到配置**的
> 环境里（比如测试）执行器根本不会注册，任务中心会报「尚无执行器」。那是环境差异，不是 bug。

## 4. `commands/` —— 斜杠命令

### 导出形态

```js
export const name = ['命令名', '别名'];   // 或字符串
export const handler = async (ctx) => { ... };
export default { name, handler };
```

或用 `lib/pure/card-kit.mjs` 的 `cardCommand({ id, names, description, usage })`。

### 返回值决定消息形态

| 返回 | 效果 |
|---|---|
| `string` | 直接发这段文本（**死模板，不带人格**） |
| `{ kind: 'text', content }` | 同上 |
| `{ wake: { content } }` | **注入一条合成消息让 AI 带人格开口**（推荐） |
| `undefined` | 什么都不发（自己已经用 `ctx.markdown` 发过了） |

> 想让命令的回复「像人说的」，用 `{ wake }`，别返回拼接好的字符串。

### 坑

- 命令需要**重启宿主**才生效（`/tools-reload` 不覆盖 commands）。
- 群聊里斜杠命令默认也要 @ —— 除非被 `aaa-addressed-command-gate` 之类的入站扩展放行。

## 5. `tools/` —— AI 可调工具

### 导出形态

```js
export default {
  name: 'my_tool',
  description: '给模型看的说明',
  inputSchema: {            // ★ 扁平写法，不要包 JSON Schema
    action: { type: 'string', required: true, description: '...' },
    limit:  { type: 'number', description: '...' },
  },
  expose: 'qq',             // 可选；'all' 才会注册到非 QQ 会话
  enabled: (env) => true,   // 可选，慎用（见下）
  async run(args, env) { ... },
};
```

### 坑

- **`inputSchema` 必须是扁平表**：`{ 字段名: { type, required, description } }`。
  写成 `{ type: 'object', properties: {...} }` 会被当成「一个叫 type 的字段」。
- **限制行为要改 `run()` 的返回值，不要用 `enabled()` 动态消失。**
  工具表一变，整个 system prompt 前缀失效，那一轮全部上下文重算（很贵）。
- 工具返回值会被归一化成 `{ ok, msg }` 后交给模型。**多返回的字段模型看不到**。
- 需要跨通道（web / 终端）可用才写 `expose: 'all'`；`'qq'` 等同于不写。

## 6. `botplay/` —— 卡片事件

### 导出形态

```js
export default {
  name: 'my-card',
  onInit(ctx) { ... },        // 首次加载 / 发卡
  onClick(ctx, info) { ... }, // 按钮被点
  onTick(ctx) { ... },        // 可选，每分钟扫一次
  onExpire(ctx) { ... },      // 可选，卡片过期
  onDispose(ctx) { ... },     // 可选，卸载/热重载
};
```

### 坑（这个扩展点最特殊）

- **只从 `{dataRoot}/.qqbot-extensions/botplay/` 加载**，不从扩展包加载。
  本包靠启动时自动复制同步（见 README「关于 botplay」）。
- 卡片里的相对 import（`../lib/xxx.mjs`）需要 `{dataRoot}/.qqbot-extensions/lib/` 整棵树。
- 群号在 **`ctx.event.peerId`**，点击者在 **`ctx.user.openid`**（这套 ctx 和 `tools` 的 `caps` **形状不同**）。
- 卡片必须**至少有一个按钮**，否则 QQ 拒发。
- 按钮回调 `data` 必须是 `ext:<工具名>:<cardId>:<buttonId>` 四段。

## 7. 怎么确认「我的扩展被加载了」

| 扩展点 | 判据 |
|---|---|
| `inbound/` | 用插件真实加载器看 `skipped` 是否为 0（见下） |
| `outbound/` | 启动日志有 `[ext-outbound] 启动装载 N 个出站扩展: ...` |
| `hooks/` | 你的 `run()` 里打日志；或看它写出的状态文件 |
| `commands/` | QQ 里敲一下，看有没有反应 |
| `tools/` | 让 AI 调一次；或看工具列表 |
| `botplay/` | `{dataRoot}/.qqbot-extensions/botplay/botplay-ext.log` 里的「已加载模块」 |

**inbound 装载自检**（最容易被静默跳过的一层）：

```bash
node --input-type=module -e "
const P = '<你的 dsh-qqbot>/dist/features/ext-inbound.js';
const { loadInboundExtensions } = await import('file://' + P);
const r = await loadInboundExtensions({
  dataRoot: '<你的 dataRoot>',
  logger: { info(){}, warn: (m) => console.log('WARN', m) },
});
console.log('total=' + r.total, 'skipped=' + r.skipped);
console.log('已装载:', r.extensions.map((e) => e.file).join(', '));
"
```

`skipped > 0` 就说明有文件形态不对 —— 而它**不会在正常运行时告诉你**。
